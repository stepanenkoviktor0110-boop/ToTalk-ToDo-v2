# User Spec: MVP Core — голосовые в задачи

## Что делаем

Telegram-бот ToTalk-ToDo, который принимает пересланные голосовые сообщения и превращает их в чёткий пронумерованный список задач. Бот убирает словесный мусор, разрешает неопределённые ссылки ("тот мужик" → "уточнить у Ани"), упорядочивает задачи по зависимостям. Несколько пересланных голосовых обрабатываются как единый контекст. После каждого результата бот собирает обратную связь (оценка 1-5, комментарий, согласие на прослушивание). Ведётся база пользователей с триал-системой (30+20 бесплатных голосовых).

## Зачем

Люди говорят как думают — хаотично, с оговорками и незаконченными мыслями. Сейчас нет инструмента, который превращает такую речь в план действий. ToTalk-ToDo решает эту проблему: надиктовал → получил список конкретных шагов. Экономия времени и когнитивной нагрузки для людей, которым проще говорить, чем писать.

## Как должно работать

### Сценарий 1: Одно голосовое

1. Пользователь пересылает голосовое сообщение боту
2. Бот отправляет "Обрабатываю голосовое..." (если обработка >5 сек)
3. Бот скачивает аудио → отправляет в faster-whisper → получает транскрипт → отправляет в GigaChat с системным промптом → получает список задач
4. Бот отправляет пронумерованный список задач
5. Под списком — inline-кнопки оценки: 1 2 3 4 5
6. Пользователь нажимает оценку
7. Если оценка < 5 → бот просит короткий текстовый комментарий
8. После комментария → бот спрашивает "Можно прослушать твоё голосовое для улучшения качества? Да / Нет"
9. Если "Да" — аудиофайл сохраняется. Если "Нет" — не сохраняется.
10. Бот благодарит за обратную связь

### Сценарий 2: Несколько голосовых

1. Пользователь пересылает несколько голосовых одновременно
2. Бот получает первое → запускает буфер 3-5 секунд
3. За время буфера приходят остальные голосовые
4. Бот транскрибирует все → объединяет транскрипты в единый текст → отправляет в GigaChat как единый контекст
5. Результат — один общий список задач из всех голосовых
6. Далее — тот же фидбек-флоу (оценка → комментарий → согласие)

### Сценарий 3: Первый контакт

1. Пользователь отправляет /start
2. Бот: приветствие, объяснение что делать ("Перешли мне голосовое — я превращу его в список задач"), информация о триале ("У тебя 30 бесплатных голосовых")
3. Пользователь автоматически регистрируется в БД

### Сценарий 4: Триал исчерпан (30 голосовых)

1. Пользователь отправляет голосовое
2. Бот: "Лимит исчерпан. Ответь на 4 вопроса о боте — получишь ещё 20 голосовых"
3. Бот последовательно задаёт вопросы:
   - "Что тебе понравилось в боте?"
   - "Что не понравилось или работало плохо?"
   - "Чего не хватает?"
   - "Общая оценка от 1 до 5"
4. Бот проверяет ответы на адекватность через LLM (sanity check). Если мусор — просит ответить нормально. При повторном мусоре — отказ в дополнительных кредитах.
5. Если ответы адекватные — разблокировка +20 голосовых
6. После исчерпания 50 голосовых (30+20) — полная блокировка в MVP

### Сценарий 5: Не-голосовое сообщение

1. Пользователь отправляет текст, фото, стикер и т.д.
2. Бот: "Перешли мне голосовое сообщение — я превращу его в список задач"

## Критерии приёмки

- [ ] Бот принимает пересланное голосовое и возвращает нумерованный список задач
- [ ] Словесный мусор удалён, извлечены конкретные действия
- [ ] Неопределённые ссылки ("тот мужик", "Аня знает") → задачи-уточнения
- [ ] Задачи упорядочены по зависимостям
- [ ] Несколько пересланных голосовых (буфер 3-5 сек) → единый контекст → один список задач
- [ ] Если задач не найдено → явное сообщение пользователю
- [ ] Если >10 задач → просьба разбить на части
- [ ] Статус "обрабатываю..." при >5 сек обработки
- [ ] Предупреждение при голосовом >3 мин
- [ ] Транскрипт обрезается до 4000 символов с уведомлением пользователю
- [ ] Inline-кнопки 1-5 после каждого списка задач
- [ ] При оценке <5 → запрос текстового комментария
- [ ] После комментария → запрос согласия на прослушивание (Да/Нет), каждый раз отдельно
- [ ] Аудиофайл сохраняется только при согласии
- [ ] Пользователь регистрируется в БД при первом контакте
- [ ] Счётчик использованных голосовых ведётся корректно
- [ ] Триал: 30 бесплатных → форма обратной связи (4 вопроса) → +20 → полная блокировка
- [ ] Форма обратной связи: sanity check через LLM, мусорные ответы не принимаются
- [ ] /start — приветствие + инструкция + триал-инфо
- [ ] Не-голосовые сообщения → объяснение что делать
- [ ] Ошибка транскрипции → понятное сообщение
- [ ] Ошибка GigaChat → понятное сообщение + retry один раз
- [ ] Бот не падает при любом типе входящего сообщения
- [ ] Время ответа <30 сек для голосового до 1 мин
- [ ] Каждый запрос логируется (user_id, duration, task_count) + все ошибки

## Ограничения

- **GigaChat free tier:** 1М токенов/год — хватает на ~1000 голосовых. Достаточно для MVP (5 тестеров).
- **VPS:** 37.233.82.205, ресурсы разделены с другими ботами и сервисами (faster-whisper, n8n).
- **5 тестеров:** не нужна очередь запросов, `better-sqlite3` (синхронный) допустим.
- **Русский язык:** основной и единственный в MVP.
- **Голосовые пересылаются:** не записываются в чате, а форвардятся из других чатов.
- **Транскрипт:** обрезается до 4000 символов перед отправкой в GigaChat.
- **Разбивка аудио по паузам:** отложена на v2 (требует ffmpeg).
- **Монетизация (10/день, пакеты):** отложена на v2. В MVP после 50 голосовых — полная блокировка.

## Риски

- **GigaChat качество экстракции задач из разговорной речи.** Митигация: LLM-абстракция позволяет заменить провайдера на DeepSeek/Claude через конфиг.
- **GigaChat TLS — сертификат Сбера не в стандартном CA-хранилище Node.js.** Митигация: добавить Sberbank CA cert bundle в конфигурацию.
- **GigaChat OAuth2 токен истекает во время запроса.** Митигация: проактивная проверка срока действия перед каждым запросом (refresh если <60 сек), retry на 401.
- **faster-whisper API контракт не верифицирован.** Митигация: проверить формат запроса/ответа через curl на VPS до начала разработки.
- **Multi-voice race condition — голосовые приходят как отдельные сообщения.** Митигация: per-chat debounce буфер 3-5 сек.

## Технические решения

- Используем GigaChat API (бесплатный тир), потому что не требует VPN, поддерживает русский, оплата в рублях.
- За GigaChat стоит LLM-абстракция (интерфейс провайдера), потому что качество GigaChat может не устроить и нужна возможность быстро переключиться.
- Системный промпт — отдельный файл `prompts/task-extraction.md`, потому что итерации промпта не должны требовать изменения кода.
- SQLite через `better-sqlite3` (синхронный), потому что для 5 тестеров блокировка event loop незначительна, а простота важнее.
- grammy для Telegram, потому что ESM-native, лёгкий, бесплатный, хорошо документирован.
- Node.js 22 ESM (`"type": "module"`), потому что современный стандарт для нового проекта.
- Фидбек-сессия: `voice_request_id` хранится в grammy session middleware. Если пользователь не оценил и прислал новое голосовое — предыдущий фидбек теряется (не блокируем).
- Разбивку аудио по паузам (ffmpeg) не делаем в MVP, потому что для голосовых до 5 мин faster-whisper справляется.
- После 50 голосовых — полная блокировка (не 10/день), потому что монетизация — это v2.

## Тестирование

**Unit-тесты:** делаются всегда, не обсуждаются.

**Интеграционные тесты:** делаем — полный pipeline с мок-транскрипцией и мок-LLM. Проверяем что данные корректно проходят через все этапы.

**E2E тесты:** ручной smoke-test с реальным ботом в Telegram (5 тестовых голосовых с разными сценариями). Автоматизация E2E в MVP не делается.

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|-------------------|
| 1. Запустить unit-тесты | `npm test` | Все тесты проходят |
| 2. Проверить что бот запускается без ошибок | bash (`node src/bot.js`) | Процесс запущен, нет ошибок в stdout |
| 3. Проверить структуру БД | bash (`sqlite3 db.sqlite .tables`) | Таблицы users, voice_requests, feedback существуют |

### Пользователь проверяет

- Отправить /start — должно прийти приветствие с инструкцией и инфо о триале
- Переслать простое голосовое ("позвонить маме") — должен прийти список с 1 задачей + кнопки оценки
- Переслать голосовое с неопределённостью ("ну тот мужик, Аня знает") — должна появиться задача-уточнение
- Переслать 3 голосовых одновременно — должен прийти один объединённый список
- Отправить текстовое сообщение — бот должен попросить голосовое
- После 30 голосовых — должна запуститься форма обратной связи
- Настроить Telegram MCP для автоматизации post-deploy проверок в будущем
