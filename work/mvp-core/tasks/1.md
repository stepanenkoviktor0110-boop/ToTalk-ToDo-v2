# Task 1: Project Scaffold + SQLite Layer

## Required Skills

Before starting, load:
- `/skill:infrastructure-setup` — [skills/infrastructure-setup/SKILL.md](~/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Initialize the Node.js project from scratch: ESM configuration, folder structure, all base dependencies, `.gitignore` additions, and `.env.example`. Then build the complete SQLite database layer — connection singleton, migration runner, migration SQL for all 4 tables, and all 11 named query functions.

This task is the foundation for the entire MVP. Every subsequent task (bot entry point, handlers, services) depends on the DB layer and project structure created here. Nothing else can start until this is done and verified.

## What to do

1. **Initialize `package.json`** with `"type": "module"` (ESM), `"engines": { "node": ">=22" }`, project name `totalk-todo`, and install 4 dependencies: `grammy`, `better-sqlite3`, `node-fetch` (v3), `dotenv`. Add test script: `"test": "node --experimental-vm-modules node_modules/.bin/jest"`.

2. **Create folder structure** — empty directories that later tasks will populate:
   - `src/db/migrations/`
   - `src/services/llm/`
   - `src/handlers/`
   - `src/utils/`
   - `prompts/`
   - `certs/`
   - `data/` (with `.gitkeep` so git tracks the directory)
   - `tests/`

3. **Update `.gitignore`** — add `data/`, `*.db` entries (database files must never be committed — they contain PII per Decision 20).

4. **Create `.env.example`** with all environment variables the project will need: `TELEGRAM_BOT_TOKEN`, `GIGACHAT_CLIENT_ID`, `GIGACHAT_CLIENT_SECRET`, `WHISPER_URL` (default `http://localhost:8765`), `DB_PATH` (default `data/bot.db`).

5. **Write migration SQL** in `src/db/migrations/001_initial.sql` — CREATE TABLE statements for all 4 tables: `users`, `voice_requests`, `feedback`, `survey_responses`. Include all columns, constraints, defaults, and foreign keys exactly as specified in the tech-spec schema.

6. **Build `src/db/index.js`** — SQLite connection singleton:
   - Read `DB_PATH` from env (default `data/bot.db`)
   - Auto-create the `data/` directory if it does not exist
   - Open the database with better-sqlite3
   - Enable WAL mode and foreign keys
   - Implement a migration runner that reads `.sql` files from `src/db/migrations/` in alphabetical order and executes them (track applied migrations to avoid re-running)
   - Export the database instance and a `runMigrations()` function

7. **Build `src/db/queries.js`** — all 11 named query functions:
   - `upsertUser(telegramUserId, telegramUsername)` — INSERT OR UPDATE, set `last_active_at` to now on update
   - `createVoiceRequest(userId, fileId, durationSeconds)` — INSERT, return the new row
   - `updateVoiceRequest(id, { taskCount, transcriptLength, audioPath })` — UPDATE specified fields
   - `saveFeedback(voiceRequestId, rating, comment, voiceConsent)` — INSERT feedback row
   - `saveSurveyResponse(userId, questionNum, answer, isAdequate, rejectionReason)` — INSERT survey answer
   - `getUserByTelegramId(telegramUserId)` — SELECT user by telegram_user_id
   - `decrementTrial(userId)` — decrement `trial_remaining` by 1, return new value
   - `advanceSurveyProgress(userId)` — increment `survey_progress` by 1
   - `completeSurvey(userId)` — set `trial_phase=2`, `trial_remaining=20`
   - `blockSurvey(userId)` — set `survey_blocked=1`
   - `exhaustTrial(userId)` — set `trial_phase=3`, `trial_remaining=0`

8. **Write unit tests** in `tests/db.test.js` using Jest with in-memory SQLite (`:memory:`). Cover all query functions and trial state transitions (see TDD Anchor below).

## TDD Anchor

- `tests/db.test.js::upsertUser creates new user` — insert new user, verify defaults: trial_remaining=30, trial_phase=1, survey_progress=0, total_voice_count=0
- `tests/db.test.js::upsertUser updates existing user` — upsert same telegram_user_id twice, verify last_active_at is updated on second call
- `tests/db.test.js::createVoiceRequest inserts record` — create a voice request, verify user_id, telegram_file_id, duration_seconds are stored correctly
- `tests/db.test.js::updateVoiceRequest updates fields` — create a voice request, then update taskCount and transcriptLength, verify updated values
- `tests/db.test.js::saveFeedback inserts record` — save feedback with rating=3, comment, voiceConsent=1, verify all fields stored
- `tests/db.test.js::saveSurveyResponse inserts record` — save survey response, verify question_num, answer, is_adequate fields
- `tests/db.test.js::getUserByTelegramId returns user` — create user, retrieve by telegram_user_id, verify match
- `tests/db.test.js::getUserByTelegramId returns undefined for missing user` — query non-existent user, verify returns undefined/null
- `tests/db.test.js::decrementTrial returns new value` — create user (trial_remaining=30), decrement, verify returns 29
- `tests/db.test.js::trial counter operations` — full lifecycle: decrementTrial down from 30 to 0, then completeSurvey sets trial_phase=2 and trial_remaining=20, then exhaustTrial sets trial_phase=3 and trial_remaining=0
- `tests/db.test.js::advanceSurveyProgress increments` — create user, call advanceSurveyProgress twice, verify survey_progress=2
- `tests/db.test.js::blockSurvey sets flag` — create user, call blockSurvey, verify survey_blocked=1

## Details

**Files:**

- `package.json` — Does not exist yet. Create with `npm init -y`, then set `"type": "module"`, add `"engines"`, install deps. Use Jest for testing: add `jest` as devDependency, configure `"test"` script with `--experimental-vm-modules` flag for ESM support. Add `jest.config.js` with `transform: {}` for native ESM.

- `.gitignore` — Already exists with standard patterns (node_modules, .env, logs, etc.). Add two lines: `data/` and `*.db`. The existing `.env` and `.env.*` patterns already cover secrets; the `!.env.example` exception is already in place.

- `src/db/index.js` — New file. Connection singleton pattern: module-level variable holding the Database instance, initialized on first call or via explicit `initDb()`. The migration runner should: (1) create a `_migrations` table if not exists, (2) read all `.sql` files from `src/db/migrations/` sorted alphabetically, (3) skip files already recorded in `_migrations`, (4) execute new ones inside a transaction, (5) record each applied migration. Export: `getDb()`, `runMigrations()`, and optionally `initDb(dbPath)` for test use with `:memory:`.

- `src/db/queries.js` — New file. Import `getDb` from `./index.js`. Each function gets the db instance via `getDb()` and runs a prepared statement. For `upsertUser`: use `INSERT ... ON CONFLICT(telegram_user_id) DO UPDATE SET telegram_username=excluded.telegram_username, last_active_at=CURRENT_TIMESTAMP`. For `decrementTrial`: use `UPDATE ... SET trial_remaining = trial_remaining - 1 WHERE id = ? RETURNING trial_remaining` (or run UPDATE then SELECT since better-sqlite3 supports RETURNING in newer SQLite versions).

- `src/db/migrations/001_initial.sql` — New file. All 4 CREATE TABLE statements. Use exact schema from tech-spec (users, voice_requests, feedback, survey_responses). Include all CHECK constraints, DEFAULT values, FOREIGN KEY references.

- `.env.example` — New file. Template with placeholder values and comments explaining each variable.

- `tests/db.test.js` — New file. Each test gets a fresh in-memory database by calling `initDb(':memory:')` + `runMigrations()` in `beforeEach`. This ensures test isolation. Import query functions and test each one.

**Dependencies:**

- Runtime: `grammy`, `better-sqlite3`, `node-fetch` (v3), `dotenv`
- Dev: `jest`, `@jest/globals` (for ESM-compatible test imports)
- No task dependencies (Wave 1, independent)

**Edge cases:**

- `data/` directory does not exist on first run — `initDb()` must create it via `fs.mkdirSync(path.dirname(dbPath), { recursive: true })`
- Migration files must be idempotent — use `CREATE TABLE IF NOT EXISTS` or track applied migrations in a metadata table
- `upsertUser` called with same `telegram_user_id` but different `telegram_username` — username should be updated
- `decrementTrial` on user with `trial_remaining=0` — should not go negative. Add a guard: only decrement if `trial_remaining > 0`, return the new value (0 if already at 0)
- `updateVoiceRequest` receives partial fields — only update the fields that are provided (not null/undefined)
- In-memory SQLite for tests does not persist `_migrations` table across tests — this is correct behavior since each test creates a fresh DB

**Implementation hints:**

- better-sqlite3 is synchronous — no `async/await` needed for DB operations. All query functions are regular (non-async) functions.
- For Jest ESM: use `--experimental-vm-modules` in the test script. In `jest.config.js`, set `transform: {}` to disable transform (native ESM). Import test utilities from `@jest/globals` (`describe`, `it`, `expect`, `beforeEach`).
- The `RETURNING` clause works in SQLite 3.35+ (better-sqlite3 bundles a recent version). Use it for `decrementTrial` to avoid a second SELECT query.
- Enable WAL mode right after opening: `db.pragma('journal_mode = WAL')`. Enable foreign keys: `db.pragma('foreign_keys = ON')`.
- For the migration runner, use `fs.readdirSync` to list files, `path.join` to build paths, `fs.readFileSync` to load SQL, and `db.exec()` to run multi-statement SQL.
