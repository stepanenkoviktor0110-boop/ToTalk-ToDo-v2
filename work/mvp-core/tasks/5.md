# Task 5: Transcription + Task Extraction Services

## Required Skills

Перед выполнением задачи загрузи:

## Description

Build two core service modules that form the middle of the voice-to-tasks pipeline: the transcription HTTP client and the task extraction orchestrator.

**Transcription service** (`src/services/transcription.js`) is an HTTP client for the faster-whisper server already running on VPS at `localhost:8765`. It accepts an audio buffer (or file path), sends it as multipart/form-data POST to `/transcribe`, and returns the transcript text. Uses a 20-second timeout via AbortController (Decision 14).

**Task extractor service** (`src/services/taskExtractor.js`) orchestrates the LLM call: reads the system prompt from `prompts/task-extraction.md`, concatenates transcript(s), truncates to 4000 chars if needed (Decision 4), calls the LLM provider's `complete()` method, and parses the response. It validates the LLM response format -- expects either a numbered list (`N. Task text`), the `__NO_TASKS__` marker, or the `__TOO_MANY_TASKS__` marker. If the response doesn't match any expected format, returns a generic error. This service depends on Task 2 (LLM provider) and Task 3 (system prompt).

## What to do

1. Create `src/services/transcription.js` -- faster-whisper HTTP client
   - Export a `transcribe(audioBuffer, filename)` function
   - POST multipart/form-data to `WHISPER_URL` env var (default `http://localhost:8765/transcribe`)
   - Use `node-fetch` v3 with its built-in FormData and Blob (Decision 7 -- do NOT use `form-data` npm package)
   - Set 20-second timeout via AbortController (Decision 14)
   - Return the transcript text string on success
   - Throw a descriptive error on HTTP failure or timeout (no credential leaking per Decision 16)
   - Accept constructor injection of `fetchFn` for testability (same pattern as GigaChat provider)

2. Create `src/services/taskExtractor.js` -- task extraction orchestrator
   - Export an `extractTasks(transcripts, llmProvider)` function
   - Accept an array of transcript strings (from single or multi-voice)
   - Concatenate transcripts with newline separator
   - Truncate combined text to 4000 characters if it exceeds the limit (Decision 4); return a `truncated: true` flag when this happens
   - Read system prompt from `prompts/task-extraction.md` using `fs.readFileSync`
   - Call `llmProvider.complete(systemPrompt, combinedTranscript)`
   - Parse the LLM response:
     - If response contains `__NO_TASKS__` marker -- return `{ tasks: [], marker: 'no_tasks' }`
     - If response contains `__TOO_MANY_TASKS__` marker -- return `{ tasks: [], marker: 'too_many_tasks' }`
     - If response matches numbered list format (lines like `N. Text`) -- extract tasks array, return `{ tasks: [...], marker: null }`
     - If response doesn't match any expected format -- return `{ tasks: [], marker: null, error: 'format_error' }`
   - Include `truncated` boolean in the return object

3. Write comprehensive tests before implementation (TDD)

## Details

**Files:**

`src/services/transcription.js` -- new file. HTTP client for faster-whisper. Exports `transcribe(audioBuffer, filename, options?)` function. Use the same dependency injection pattern as `src/services/llm/gigachat.js` (constructor injection of `fetchFn` for testing). The faster-whisper server expects a multipart POST with a `file` field and returns JSON with a `text` field containing the transcript.

`src/services/taskExtractor.js` -- new file. Orchestrator that ties together the system prompt and LLM provider. Exports `extractTasks(transcripts, llmProvider)` function. The `transcripts` parameter is an array of strings (supports multi-voice from Task 6). The `llmProvider` is an instance implementing the `LLMProvider.complete()` contract from Task 2.

**Dependencies:**
- Task 2 (LLM Provider + GigaChat) -- provides the `LLMProvider` interface and `complete()` contract used by taskExtractor
- Task 3 (System Prompt) -- provides `prompts/task-extraction.md` file read by taskExtractor
- `node-fetch` v3 -- already in package.json from Task 2. Use its built-in `FormData` and `Blob` (Decision 7)
- `fs` (Node.js built-in) -- for reading the prompt file

**Edge cases:**
- Empty transcript array -- should handle gracefully (pass empty string to LLM or return early)
- Transcript exactly at 4000 chars -- should NOT be marked as truncated
- Transcript at 4001 chars -- truncated to 4000, `truncated: true`
- LLM returns numbered list with extra whitespace or blank lines -- parser should be tolerant
- LLM returns marker with surrounding whitespace -- should still be recognized
- Fetch timeout fires -- error should be descriptive ("Transcription timeout after 20s") without exposing internal URLs in production
- faster-whisper returns non-JSON response -- should throw descriptive error

**Implementation hints:**
- For `transcribe()`, create a `Blob` from the audio buffer and append to `FormData` with the filename. node-fetch v3's built-in FormData handles the multipart encoding.
- For numbered list parsing, a regex like `/^\d+\.\s+(.+)$/gm` works well to extract task text from each line.
- Read the prompt file once at module load time (or lazily cache it) -- it doesn't change at runtime. `fs.readFileSync` is fine for this (same pattern as SQLite being synchronous per Decision 6).
- The `fetchFn` injection pattern: export a factory function or accept `fetch` as a parameter, defaulting to the real `node-fetch` import. See `src/services/llm/gigachat.js` for the established pattern.
