# Task 2: LLM Provider Abstraction + GigaChat Client

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Create the LLM provider abstraction layer and its first concrete implementation — the GigaChat client. This is a foundational piece that all task extraction logic (Wave 2, Task 5) depends on.

The provider interface defines a single `complete(systemPrompt, userMessage) → Promise<string>` contract. The GigaChat implementation handles OAuth2 token lifecycle (proactive refresh before expiry, retry on 401), general retry on 5xx/network errors, 15-second timeout via AbortController, and TLS trust for Sberbank's CA certificate.

Credential sanitization is critical: error paths must never leak authorization headers, API keys, or tokens into log output. This is enforced by unit tests.

The abstraction enables swapping LLM providers (DeepSeek, Claude, etc.) via config without touching business logic.

## What to do

1. **Create `src/services/llm/provider.js`** — Define the LLM provider interface as a base class or documented contract. Export a class/object with a single async method `complete(systemPrompt, userMessage)` that returns `Promise<string>`. The base class should throw "not implemented" if called directly. This file is the contract that all LLM implementations must follow.

2. **Obtain and bundle the Sberbank CA certificate** — Place the Russian Trusted Root CA certificate into `certs/russian_trusted_root_ca.cer`. This certificate is needed for TLS connections to GigaChat endpoints (`ngw.devices.sberbank.ru` and `gigachat.devices.sberbank.ru`). The cert is loaded at GigaChat client initialization time and passed to the HTTPS agent.

3. **Create `src/services/llm/gigachat.js`** — Implement the GigaChat provider class extending/implementing the provider interface. The class must handle:
   - **OAuth2 token acquisition:** POST to `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` with `scope=GIGACHAT_API_PERS` and `Authorization: Basic {GIGACHAT_AUTH_KEY}`. Parse `access_token` and `expires_at` from response.
   - **Proactive token refresh:** Before each `complete()` call, check if the cached token expires in less than 60 seconds. If so, fetch a new token before making the request.
   - **Chat completion request:** POST to `https://gigachat.devices.sberbank.ru/api/v1/chat/completions` with the model name, system prompt as a system message, and user message as a user message. Extract and return the `choices[0].message.content` string.
   - **Retry on 401:** If the chat completion returns 401, refresh the token and retry the request exactly once.
   - **Retry on 5xx/network error:** If the chat completion returns 5xx or a network error occurs, retry exactly once. On second failure, throw.
   - **15-second timeout:** Use AbortController with a 15s timeout on all fetch calls.
   - **TLS configuration:** Create an HTTPS agent that includes the bundled Sberbank CA cert for all requests to Sberbank/GigaChat domains.
   - **Credential sanitization:** All error handling code must strip Authorization headers and tokens before logging. On token-request failure, log only HTTP status code and error body — never serialize the request headers object.

4. **Write unit tests in `tests/llm.test.js`** — Cover all TDD anchor tests (see TDD Anchor section). Tests must mock HTTP calls (mock `node-fetch`) and verify behavior without real API calls.

5. **Verify the smoke check passes:** `node -e "import { GigaChatProvider } from './src/services/llm/gigachat.js'; console.log('import OK')"` prints "import OK".

## TDD Anchor

Write these tests BEFORE implementation. Run them, confirm they fail, then implement the code, then confirm they pass.

- `tests/llm.test.js::complete() extracts content from response` — Mock HTTP to return a valid GigaChat chat completion JSON. Call `complete()`. Verify it returns the plain string from `choices[0].message.content`, not the raw JSON object.
- `tests/llm.test.js::refreshes token when <60s to expiry` — Set the cached token's `expires_at` to 30 seconds from now. Call `complete()`. Verify that the token endpoint was called to fetch a new token before the chat completion request.
- `tests/llm.test.js::retries once on 401` — Mock the first chat completion request to return HTTP 401. Verify the client refreshes the token and retries the chat completion exactly once. On successful retry, return the content.
- `tests/llm.test.js::retries once on 5xx` — Mock the first chat completion request to return HTTP 500. Verify the client retries once. If the second attempt also fails (500), verify it throws an error.
- `tests/llm.test.js::does not retry on 4xx (non-401)` — Mock chat completion to return HTTP 400. Verify no retry attempt is made and the error is thrown immediately.
- `tests/llm.test.js::throws on timeout` — Mock a response that takes longer than 15 seconds (or simulate AbortController abort). Verify an AbortError or timeout error is thrown.
- `tests/llm.test.js::no credentials in error logs` — Simulate a GigaChat API error. Capture all console.error/console.log output during the error handling. Assert that neither the GIGACHAT_AUTH_KEY value nor any access_token substring appears in the captured output.

## Details

**Files:**

- `src/services/llm/provider.js` — New file. Define a base class `LLMProvider` with an async `complete(systemPrompt, userMessage)` method that throws "not implemented". Export the class. This serves as the contract for all LLM implementations. Consumers (taskExtractor in Task 5) will depend on this interface only, never on gigachat.js directly.

- `src/services/llm/gigachat.js` — New file. Implement `GigaChatProvider extends LLMProvider`. Constructor accepts config (or reads from env): `GIGACHAT_AUTH_KEY` (base64 client credentials for Basic auth), `GIGACHAT_MODEL` (default: `GigaChat-2`). Internal state: cached `accessToken` and `expiresAt` (unix ms). Exports the class as a named export `GigaChatProvider`.

- `certs/russian_trusted_root_ca.cer` — New file. The Russian Trusted Root CA certificate (PEM format). This is Sberbank's root CA used by `ngw.devices.sberbank.ru` and `gigachat.devices.sberbank.ru`. Download from the official MinTsifry source or extract from the GigaChat developer documentation. The cert is loaded via `fs.readFileSync` at provider construction time and passed to an HTTPS agent.

- `tests/llm.test.js` — New file. All unit tests for the LLM layer. Must mock `node-fetch` globally (jest.unstable_mockModule or similar ESM mock strategy). Each test sets up mock responses for token and/or completion endpoints, then exercises the GigaChatProvider.

**Dependencies:**

- `node-fetch` v3 — Must already be in package.json (installed by Task 1). Use `import fetch from 'node-fetch'` for HTTP calls.
- `jest`, `@jest/globals` — Installed by Task 1. If running before Task 1, install them: `npm install --save-dev jest @jest/globals`.
- Node.js built-in `https` module — For creating an Agent with custom CA cert.
- Node.js built-in `fs` — For reading the CA cert file.
- No external form-data package (Decision 7).

**Edge cases:**

- Token endpoint returns non-JSON or unexpected shape — throw a clear error without leaking headers.
- Token endpoint returns HTTP error (403, 500) — log status and body only, never the request headers object (Decision 16).
- `expires_at` field from token response is in Unix milliseconds — compare with `Date.now()`, not seconds.
- Network errors (ECONNREFUSED, ETIMEDOUT) during token fetch — should be caught and wrapped in a descriptive error. These are not retried (only chat completion retries).
- Chat completion returns valid JSON but `choices` array is empty or missing — handle gracefully, throw descriptive error.
- AbortController timeout fires during token fetch vs during chat completion — both should result in a timeout error, but only the chat completion is retried.
- Concurrent calls to `complete()` while token is being refreshed — avoid parallel token refresh; a simple "if refreshing, await the existing refresh promise" pattern is sufficient.

**Implementation hints:**

- For the HTTPS agent with custom CA, use `new https.Agent({ ca: certBuffer })` and pass it as the `agent` option to `node-fetch`. Since GigaChat uses two different domains (token endpoint on `ngw.devices.sberbank.ru`, chat on `gigachat.devices.sberbank.ru`), a single agent with the CA cert works for both.
- The OAuth2 token request uses `Content-Type: application/x-www-form-urlencoded` with body `scope=GIGACHAT_API_PERS`. Also requires a `RqUID` header with a UUID v4 value (check GigaChat docs — some API versions require this).
- For credential sanitization in error handlers: when constructing error messages or logging, explicitly extract only `status` and `statusText` from the response. Never spread or JSON.stringify the full request options object.
- For ESM test mocking: Jest ESM module mocking is still experimental. Consider using `jest.unstable_mockModule('node-fetch', ...)` before dynamic `import()` of the module under test. Alternatively, inject fetch as a dependency via constructor parameter for easier testing.
- The `GIGACHAT_AUTH_KEY` env var is already the base64-encoded credentials string — use it directly in `Authorization: Basic {GIGACHAT_AUTH_KEY}` without additional encoding.
- AbortController: create a new controller + `setTimeout(() => controller.abort(), 15000)` for each fetch call. Clear the timeout on successful response to avoid memory leaks.
