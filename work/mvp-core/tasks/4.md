# Task 4: Bot Entry Point + Handler Skeleton

## Required Skills

Перед выполнением задачи загрузи:

## Description

Create the grammy bot entry point (`src/bot.js`) and a centralized messages module (`src/utils/messages.js`). This is the first "live" part of the bot -- it initializes the grammy Bot instance, sets up session middleware for tracking feedback/survey state, registers the `/start` command handler, a catch-all non-voice message handler, and performs user auto-registration in the database on first contact.

This task establishes the bot process that all subsequent handlers (voice, feedback) will plug into. It depends on Task 1 (SQLite layer) because the `/start` handler calls `upsertUser` to register new users, and initialization calls `initDb` + `runMigrations`.

The session state structure must match the tech-spec contract so that later tasks (voice handler, feedback handler) can rely on it:
```js
{ awaitingFeedback: false, voiceRequestId: null, awaitingComment: false, awaitingConsent: false, inSurvey: false, surveyRetries: {} }
```

## What to do

1. Create `src/utils/messages.js` -- centralized module exporting all Russian user-facing strings as named constants. For this task, include at minimum: welcome message with trial info (30 free voices), non-voice explanation text, and a generic error message. Other tasks will add more strings as needed.

2. Create `src/bot.js` -- the bot entry point:
   - Load environment variables via dotenv
   - Initialize SQLite database (`initDb()`) and run migrations (`runMigrations()`)
   - Create grammy `Bot` instance with `TELEGRAM_BOT_TOKEN`
   - Configure session middleware with the initial session state from the tech-spec
   - Register `/start` command handler: call `upsertUser(ctx.from.id, ctx.from.username)`, reply with welcome message including trial info
   - Register a handler for non-voice messages (text, photo, sticker, etc.): reply with explanation text from messages module
   - Register `bot.catch()` global error handler (Decision 13): log error with timestamp, send generic error message to user, do not crash process
   - Start long polling (`bot.start()`)

3. Ensure user auto-registration happens on `/start` using the existing `upsertUser` function from `src/db/queries.js`. The function already handles both insert and update (ON CONFLICT).

**Dependencies:**

- `grammy` package -- already in package.json dependencies (installed in Task 1).
- `dotenv` package -- already in package.json dependencies (installed in Task 1).

**Edge cases:**

- User sends /start multiple times -- `upsertUser` handles this via ON CONFLICT (updates username and last_active_at).
- User has no username (`ctx.from.username` is undefined) -- pass null/undefined, `upsertUser` accepts it (username column is nullable).
- Bot token missing or invalid -- bot.start() will throw. Ensure meaningful error message on startup failure.
- Non-voice handler must NOT catch voice messages -- use grammy's filter to exclude `message:voice` from the catch-all. Voice handler registration will happen in Task 6.

**Implementation hints:**

- grammy session middleware: use `session({ initial: () => ({...}) })` with the exact shape from tech-spec Session State section.
- For the non-voice catch-all, register it after /start but filter out voice messages. grammy filter strings: `message:text`, `message:photo`, `message:sticker`, etc. Alternatively, use a negative filter or register voice handler placeholder that does nothing (to be replaced in Task 6).
- `bot.catch(err => { ... })` -- log `err.message` and `err.ctx?.chat?.id` with timestamp. Send `GENERIC_ERROR` message via `err.ctx.reply()`. Wrap reply in try-catch in case the reply itself fails.
- Decision 13: global error handler must not crash the process. Log and continue.
- Decision 12: do not log the bot token, user message content, or any credentials in error handler output.
- Decision 16: if error object contains URL with bot token, sanitize before logging (strip `/bot.../` from URL).

**Relevant tech-spec decisions:**

- Decision 9 (silent abandon): session state must support feedback interruption -- the initial state enables this.
- Decision 13 (global error handler): `bot.catch()` required.
- Decision 12 (logging): console.log with timestamps, no PII/credentials.
- Decision 16 (credential sanitization): sanitize bot token from error URLs before logging.
