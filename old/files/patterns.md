# Patterns: VoiceTask Bot

## Конвенции кода

- **Язык:** JavaScript (Node.js v22), CommonJS или ESM (определить при инициализации)
- **Стиль:** async/await везде, без callback-hell
- **Именование:** camelCase для переменных/функций, PascalCase для классов
- **Комментарии:** на русском, только для неочевидной логики

## Ключевой паттерн: Pipeline обработки голосового

Каждый голосовой проходит через чёткий pipeline. Каждый этап — отдельная функция с единственной ответственностью:

```
downloadVoice(fileId) 
  → transcribeAudio(audioBuffer) 
  → extractTasks(transcript) 
  → formatTaskList(tasks)
  → sendToUser(chatId, formatted)
```

Ошибка на любом этапе → понятное сообщение пользователю (не технический стек).

## Паттерн: Промпт-инжиниринг для экстракции задач

Системный промпт — отдельный файл `prompts/task-extraction.md`, не вшивается в код. Это позволяет итерировать промпт без изменения логики.

**Структура промпта:**
1. Роль: "Ты — ассистент по извлечению задач из речи"
2. Правила фильтрации мусора
3. Правила работы с неопределёнными референсами
4. Правила упорядочивания по зависимостям
5. Формат вывода (JSON или нумерованный список)
6. Примеры (few-shot): минимум 3 пары вход/выход

## Паттерн: Обработка неопределённостей

Три типа неопределённостей в речи:

| Тип | Пример | Обработка |
|-----|--------|-----------|
| Неизвестный человек | "ну тот мастер" | Задача-уточнение: "Выяснить контакт мастера" |
| Альтернатива ("или") | "Ваня или Андрей" | Задача-уточнение: "Определить, кто именно нужен" |
| Знает кто-то другой | "Аня знает" | Задача-делегирование: "Спросить у Ани" |

Принцип: **не угадывать, а сделать уточнение явным шагом**.

## Git Workflow

- Ветка `main` — стабильный код, деплой на VPS
- Ветка `dev` — текущая разработка
- Коммиты: `feat:`, `fix:`, `prompt:`, `refactor:`, `docs:`
- Особая метка `prompt:` — изменения только в промптах (без изменения логики)

## Стратегия тестирования

**Unit тесты** (Jest):
- `taskExtractor.js` — мокаем Claude API, тестируем разные типы речи
- `transcription.js` — мокаем faster-whisper, тестируем обработку ответа

**Integration тесты**:
- Полный pipeline на тестовых аудиофайлах (набор из 10+ реальных примеров)

**Ключевые тест-кейсы для экстракции задач:**
1. Простая одна задача без неопределённостей
2. Несколько задач в одном голосовом
3. Голосовое с явным неизвестным человеком ("Аня знает")
4. Голосовое с альтернативой ("или Ваня, или Андрей")
5. Голосовое без задач вообще (просто размышления вслух)
6. Очень короткое голосовое (< 5 секунд)
7. Голосовое с фоновым шумом (транскрипт с ошибками)

## Бизнес-правила

- Если задач не обнаружено → сообщить пользователю, не возвращать пустой список молча
- Максимум задач за один голосовой — 10 (если больше, значит голосовое слишком длинное, просить разбить)
- Время обработки > 30 секунд → отправить промежуточный статус ("обрабатываю...")
- Голосовое > 3 минут → предупредить о долгой обработке
